# Mission contribution payment methods

The contribution form collects a selected country/calling code and a national phone number. The backend derives the stored country name from the ISO country selection, validates the calling code and records contact details for each provider. Stripe/Card and PayPal appear for every country selection. Selecting Pakistan (+92) also reveals manual payment, with the existing Meezan Bank and JazzCash accounts from the registration pages. Server validation enforces the Pakistan restriction independently of the UI.

Stripe continues to offer one-time and automatic monthly giving, with existing webhook confirmation and subscription management. PayPal uses the existing client credentials and Orders API for one-time GBP payments. Choosing PayPal explicitly selects one-time giving; choosing automatic monthly giving selects Stripe. PayPal order creation uses a stable request ID and binds the order to the donor record. The return endpoint captures an approved order and verifies order ID, funding record, completed capture status, currency and exact amount before updating the payment ledger. Provider approval or a success query string alone does not confirm a contribution. Repeated confirmation cannot produce duplicate ledger entries or acknowledgments. The former permissive capture helper now delegates to this verifier.

Manual transfers record the exact entered PKR amount in minor units, with sender name, transaction reference, phone and notes. The donor submits details after making the transfer. Donation and evidence records are created atomically and start UNDER_REVIEW. Donor and admin messages say verification is pending. Only the authenticated admin review endpoint can confirm receipt; repeated approval does not repeat donor acknowledgment. A monthly manual choice records a monthly pledge, not an automatic subscription. Each future transfer needs a separate submission. No conversion rate is guessed.

Admin Mission Support includes country/phone columns, full transfer evidence in the popup and the existing Confirm / Pending / Cancel actions for manual entries. GBP and PKR amounts display in their own currencies, and net receipts are summarized separately. Local transfers are excluded from GBP totals. Stripe refund actions appear only for Stripe ledger payments; PayPal refunds remain managed in PayPal and are not automatically synchronized by this change.

## DigitalOcean configuration

No new environment variable or database migration is needed. Retain the existing mission policy/enablement variables and database/email settings. Stripe uses its existing keys and webhook. PayPal uses the same PAYPAL_CLIENT_ID and PAYPAL_CLIENT_SECRET as the existing website connection, with PAYPAL_ENV=live for real payments (sandbox otherwise). Store the client secret encrypted; do not paste credentials into chat. NEXT_PUBLIC_APP_URL remains https://www.tga-awakening.com/. Method availability is checked independently, so missing Stripe credentials do not disable configured PayPal or approved manual giving. Production manual giving requires MISSION_SUPPORT_PAYMENTS_ENABLED=true and MISSION_SUPPORT_LIVE_APPROVED=true.
