# Donation checkout and administration update

The checkout previously compared the browser Origin directly with `request.url`. Behind an ingress proxy the public HTTPS origin may differ from the internal request URL, so legitimate donors were rejected before Stripe was called. Checkout, subscription management and admin refunds now share a validator that accepts the configured `NEXT_PUBLIC_APP_URL` origin (including the two TGA domain variants), retains local same-origin handling and rejects unrelated, malformed and spoofed forwarded-header origins. No new environment variables are required. The confirmed public URL is `https://www.tga-awakening.com/`.

Admin → Mission Support now provides supporter contacts, net confirmed GBP receipts, active monthly GBP commitments and unconfirmed entries; a breakdown of every funding preference; searchable entries with status, purpose and frequency filters; and a ten-column donor table. Details open in a native modal dialog with donor fields, frequency, selected purpose, payment/subscription state, references, donor/admin notes, payment history, receipts and existing refund/manual review actions. Escape closes the dialog and native dialog focus handling keeps keyboard interaction inside it. Failed or unfinished checkouts do not count as income. Monthly commitments exclude subscriptions scheduled to cancel. GBP summary totals do not combine other currencies. Existing records use the existing database schema; no migration is needed.

Funding cards use shorter balanced copy, aligned title/description space, inset full-composition images, rounded corners and restrained numbered markers. The duplicate allocation line beneath them is removed; the donation form, accountability section and contribution terms still explain allocation. Mission columns stretch to equal height. The closing invitation uses the online teaching workspace with a faded background transition instead of a cropped learner portrait.

Validation: ESLint, TypeScript and production build; 22 isolated payment/origin tests, including a proxied checkout route with a fake Stripe provider; browser checks for retained giving preferences, mobile widths, reduced motion, complete card imagery, equal mission-column heights, filters, net receipts after refunds, popup content, reopening and Escape dismissal. Admin browser checks use synthetic records in a local isolated preview, with no production authentication changes or database writes. Live charges and production webhook delivery are not exercised by these tests.
